## Requirement
Return a real original transcript, a translated caption and AI-generated
speech on the user's Redmi Note 9 Pro; record timestamped end-of-utterance to
caption and audible-output latency. Test both directions.

## Implementation submitted
- Flutter gateway provider awaits an authenticated ready event, forwards
  16kHz PCM16 microphone frames, and shows translated transcripts and WAV voice.
- User consent checkbox gates cloud microphone processing; mock mode stays free.
- Python gateway/gateway.app accepts only MIC, ta/en, 16kHz mono PCM16,
  monotonically increasing audio sequence numbers, and a test-only token.
- Basic energy segmentation waits for ~0.5 seconds of silence; bounded at
  5 seconds before processing and at 3 queued chunks.
- Cloud workflow: gpt-transcribe → gpt-4.1-mini → gpt-4o-mini-tts.
  API key is read server-side only; transcripts and recordings are not saved.
- HTTP API unit tests use fake responses. They do not demonstrate live AI use.
- A PowerShell debug-LAN manifest script and README instructions are supplied.

## Critical model decision
gpt-realtime-translate (dedicated endpoint) does not currently support Tamil
target output. The selected segmented chain is a *different* workflow with
higher potential latency. Tamil ASR quality and TTS pronunciation have not
been tested. gpt-4o-mini-tts is scheduled for retirement on 2027-01-06.
